01 / PROJECT BRIEF

What we're building

A modular prototype for demonstrating sensor-based tilt detection and remote status reporting.

⌁

The problem

Unexpected wheelchair tilt or tipping can create a safety risk. A nearby warning and remote status update may help a caregiver become aware of a possible event.

Our approach

The MPU-6050 measures acceleration and angular motion. The STM32 evaluates sensor readings, drives a buzzer through a suitable driver, and exchanges status with the ESP8266 over UART.

PRIMARY OBJECTIVE
◎

Detect → Decide → Alert

Start with reliable local detection. Add Wi-Fi and cloud reporting only after the sensing and alarm stages work.

04 / SIMULATION PLAN

Proteus build strategy

Validate the design in small, testable steps instead of trying to simulate every module at once.

01

Confirm the firmware toolchain

Proteus 9.1 Demonstration was identified during setup. The Arduino-for-STM32 compiler appeared unconfigured, so confirm installation and model support first.

NEXT CHECK
02

Prove a GPIO output

Run a minimal LED or digital-output test on the Blue Pill model before adding sensor logic.

NOT YET VERIFIED
03

Test detection and buzzer

If MPU-6050 simulation is unavailable, use a switch or test input to exercise the alarm logic. This tests logic, not real motion sensing.

PLANNED
04

Test UART and real Wi-Fi separately

Use a virtual terminal to check serial messages; verify ESP8266 and Firebase on physical hardware if the Proteus model cannot emulate networking.

PLANNED
⌘
SIMULATION REALITY CHECK

What Proteus may not model

  • Exact MPU-6050 behaviour, unless a compatible simulation model is installed.
  • ESP-01 firmware execution and real 2.4 GHz Wi-Fi.
  • Firebase cloud access from inside the schematic.

Fallback plan

Simulate GPIO, threshold logic, buzzer and serial messages where supported. Test sensor readings and cloud updates on the real boards.
